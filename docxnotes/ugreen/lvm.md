# lvm

## 一、LVM概述

**LVM（Logical Volume Manager，逻辑卷管理器）**  是Linux环境下对磁盘分区进行管理的一种机制。它在硬盘分区和文件系统之间添加了一个逻辑层，为文件系统屏蔽下层磁盘布局，提供抽象的存储空间。

简单来说，LVM可以：

- 把一个大容量物理磁盘划分为若干小的虚拟磁盘
- 把几个小的物理磁盘整合成一个大的虚拟磁盘
- 实现存储空间的动态扩展和收缩

LVM的创建初衷，正是为了解决传统硬盘分区在创建后**不易修改分区大小**的缺陷。

### LVM vs 传统分区

|特性|传统分区|LVM|
| --------| --------------------------| --------------------|
|扩容|需重新分区，可能丢失数据|在线扩容，无需停机|
|跨磁盘|单个分区无法跨磁盘|可跨多个物理磁盘|
|灵活性|固定大小，难以调整|动态调整，灵活分配|
|快照|不支持|支持时间点快照|

## 二、LVM三大核心组件

LVM通过**三层抽象**来管理存储空间，从底层到上层依次是：​**物理卷（PV）→ 卷组（VG）→ 逻辑卷（LV）** 。

### 2.1 PV（Physical Volume，物理卷）

物理卷是LVM的​**最底层**，指被LVM初始化过的物理存储设备（如硬盘、SSD、分区等）。

通俗理解：​**物理磁盘就像是砖头水泥等原始建筑材料，创建物理卷相当于对这些材料进行标准化处理，做成统一的乐高积木**，变成可以随意拼接的标准化模块。

bash

```
# 将磁盘初始化为物理卷
pvcreate /dev/sdb1
# 查看物理卷信息
pvs          # 简要信息
pvdisplay    # 详细信息
```

### 2.2 VG（Volume Group，卷组）

卷组是LVM的​**中间层**​，由一个或多个物理卷组合而成的​**存储资源池**​。可以把卷组想象成一个​**虚拟的大硬盘**，其总容量等于所有成员物理卷的容量之和。

例如，有2块1TB硬盘，通过LVM将它们加入同一个卷组，该卷组容量即为​**2TB**，打破了单盘容量限制。

bash

```
# 创建卷组（将PV加入VG）
vgcreate vg_data /dev/sdb1
# 查看卷组信息
vgs          # 简要信息
vgdisplay    # 详细信息
```

### 2.3 LV（Logical Volume，逻辑卷）

逻辑卷是LVM的​**最顶层**​，从卷组中划分出的​**虚拟分区**，供操作系统直接使用。在逻辑卷上可以创建文件系统（如ext4、xfs）并挂载使用。

bash

```
# 从卷组创建逻辑卷
lvcreate -L 100G -n lv_mysql vg_data
# 查看逻辑卷信息
lvs          # 简要信息
lvdisplay    # 详细信息

# 格式化并挂载
mkfs.xfs /dev/vg_data/lv_mysql
mount /dev/vg_data/lv_mysql /mysql
```

### 2.4 三层架构关系图

text

```
┌─────────────────────────────────────────────────┐
│                  逻辑卷 (LV)                     │  ← 用户可见的"虚拟分区"
│            /dev/vg_data/lv_mysql                │
├─────────────────────────────────────────────────┤
│                  卷组 (VG)                       │  ← 存储资源池
│                 vg_data (2TB)                   │
├───────────────────┬─────────────────────────────┤
│    物理卷 (PV)    │        物理卷 (PV)          │  ← 标准化后的物理磁盘
│   /dev/sdb (1TB)  │       /dev/sdc (1TB)       │
└───────────────────┴─────────────────────────────┘
```

三层架构的核心价值在于​**VG层将资源池化**​，对LV屏蔽了底层物理设备的类型、数量等细节，实现了​**底层解耦**。

## 三、LVM的核心优势

### 3.1 动态调整大小（在线扩容/缩容）

LVM最大的优势是可以在**不重启系统、不移动数据**的情况下，在线扩大或缩小逻辑卷的大小。

**在线扩容流程**（以XFS文件系统为例）：

bash

```
# 1. 确认卷组有足够空闲空间
vgs vg_data

# 2. 扩容逻辑卷（无需卸载！）
lvextend -L +30G /dev/vg_data/lv_mysql

# 3. 扩展文件系统（XFS）
xfs_growfs /dev/vg_data/lv_mysql

# 4. 验证扩容结果
df -h /mysql
```

**缩容注意事项**（仅EXT4支持在线缩容，XFS不支持）：

bash

```
umount /mysql              # 必须先卸载
fsck -f /dev/vg_data/lv_mysql
resize2fs /dev/vg_data/lv_mysql 20G   # 缩容文件系统
lvreduce -L 20G /dev/vg_data/lv_mysql # 缩容逻辑卷
mount /dev/vg_data/lv_mysql /mysql
```

### 3.2 虚拟存储空间

可以将多个**大小不同、类型不同**的物理磁盘整合成一个大的存储空间（VG）进行统一管理。当存储空间不足时，可以随时添加新磁盘到卷组：

bash

```
pvcreate /dev/sdd1          # 初始化新磁盘
vgextend vg_data /dev/sdd1  # 将PV加入现有卷组
```

### 3.3 快照（Snapshot）

LVM支持创建逻辑卷的**时间点副本（快照）**  ，用于备份或临时回滚，且不影响生产环境。

bash

```
# 创建快照
lvcreate -s -L 10G -n lv_mysql_snap /dev/vg_data/lv_mysql
```

快照采用**写时复制（COW）**  机制，只记录原始卷的变化部分，因此非常节省空间。但需注意：​**如果快照空间被写满，快照将失效**。

## 四、LVM在NAS存储中的应用

结合你之前提到的NAS存储故障排查，LVM在NAS环境中的典型应用场景包括：

|场景|LVM的作用|
| ------| --------------------------------------------|
|**存储池扩容**|向卷组添加新硬盘，在线扩展逻辑卷，无需停机|
|**数据迁移**|利用`pvmove`在磁盘间在线迁移数据|
|**备份保护**|创建快照后进行一致性备份，不影响生产|
|**灵活分区**|根据需求动态调整各共享文件夹的容量|

## 五、常用LVM命令速查

|操作|命令|
| ----------------------| ------------|
|创建物理卷|`pvcreate /dev/sdX`|
|查看物理卷|`pvs`​ 或 `pvdisplay`|
|创建卷组|`vgcreate vg_name /dev/sdX`|
|查看卷组|`vgs`​ 或 `vgdisplay`|
|创建逻辑卷|`lvcreate -L 100G -n lv_name vg_name`|
|查看逻辑卷|`lvs`​ 或 `lvdisplay`|
|扩容逻辑卷|`lvextend -L +30G /dev/vg_name/lv_name`|
|缩容逻辑卷|`lvreduce -L 20G /dev/vg_name/lv_name`|
|扩展文件系统（EXT4）|`resize2fs /dev/vg_name/lv_name`|
|扩展文件系统（XFS）|`xfs_growfs /mount_point`|
|创建快照|`lvcreate -s -L 10G -n snap_name /dev/vg_name/lv_name`|
|添加磁盘到卷组|`vgextend vg_name /dev/sdX`|
|从卷组移除磁盘|`vgreduce vg_name /dev/sdX`|

## 六、总结

LVM是Linux存储管理的核心工具，它通过 **PV → VG → LV** 三层抽象，将物理磁盘虚拟化，提供了：

1. **弹性扩展** — 在线扩容/缩容，无需停机
2. **跨盘整合** — 打破单盘容量限制
3. **快照保护** — 时间点备份与回滚
4. **统一管理** — 屏蔽底层硬件差异

对于NAS等需要灵活管理存储的设备，LVM是构建存储池的基础技术之一。理解LVM的工作原理，有助于更好地进行存储故障排查和容量规划。
